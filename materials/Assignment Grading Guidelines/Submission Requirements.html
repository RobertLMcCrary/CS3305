Assignment Submission Requirements

Style Requirements for Assignments

Besides solving the programming exercises, there are several additional requirements when you submit your assignment. Note that these are very important and point deduction will be applied (see the assignment  grading rubric) if you do not meet these requirements:

  1. Proper header for each program as described below.
  2. Separate the code into sections with block comments and inline comments for Declarations, Reading Inputs, Calculations, and Output code segments. 
  3. Indent and space out code segments properly. 
  4. Read the assignment grading rubric and make sure you meet all item to avoid point deductions

Requirements for Comments in Source Files

Source code files must be neatly formatted, including consistent indentation to enhance code readability.

Documentation of source code (header blocks and inline comments) must be neatly formatted.

Every source file you turn must include author header (block of comments at the beginning of the file) with the following information: 

  • CS 3305/01
  • Term
  • Your name
  • Professor's name
  • The assignment number in the form: Assignment #.
  • IDE name

Use the following format for the author header each program:

/*
 * Class:       CS 3305/01
 * Term:        Fall 2025
 * Name:        ...
 * Instructor:  Dr. Hisham Haddad
 * Assignment:  ...
 * IDE       :  ...
 */

For example, Alan Turing in section W01 would have the following header block at the beginning of each source code files for this assignment #3:

/*
 * Class:       CS 3305/W01 
 * Term:        Fall 2025
 * Name:        Alan Turing
 * Professor:   Dr. Hisham Haddad
 * Assignment:  3
 * IDE:         IntelliJ
 */


Always carefully read the grading rubric

Upload only source files (.java files) to the assignment submission folder in D2L.

Please DO NOT use zip files. Zipped submissions will not be graded!

No email submissions, only in D2L.
